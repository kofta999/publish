##### Content
They're servers that redirect forward internet traffic to multiple servers (EC2) instances
### Uses
- Spread load across multiple machines
- Expose a single point of access to your app
- Seamlessly handle instance failures
- Do regular health checks to instances
- Provide SSL termination
- Enforce instance stickiness with cookies (NLB doesn't use cookies)
- High availability across zones
- Separate public traffic from private one

### Why ELB
- It's managed (AWS guarantees it's working, will take care of upgrades, simple config)
- More expensive than your own LB but less effort
- Integrated with many AWS services

### Types
- **Classic** (v1 - 2009)
	- L4 / L7
	- Deprecated but still used (e.g. Kubernetes LB)
	- HTTP, HTTPS, TCP, SSL
	- Supports 1 SSL cert
- **Application** (v2 - 2016)
	- L7
	- HTTP, HTTP/2, HTTPS, WebSockets
	- Supports multiple listeners using SNI
- **Network** (v2 - 2017)
	- L4
	- TCP, TLS, UDP
	- Supports multiple listeners using SNI
- **Gateway** (2020)
	- L3 / IP Protocol

### ELB Sticky Sessions (Session Affinity)
Sticky sessions ensure that a specific client is always routed to the same backend instance for the duration of a session, preventing the loss of local session data.

![[Pasted image 20260311174245.png|233]]
#### Core Mechanics
- **Compatibility:** Supported by ALB and CLB (via HTTP cookies) and NLB (via Source IP).
- **Mechanism:** The LB inserts a cookie into the response; the client returns it on subsequent requests to maintain the connection to the specific target.
- **Risk:** Can cause **load imbalance**, as some instances may end up handling significantly more traffic than others if sessions are long-lived or resource-heavy.
#### Cookie Types & Names
- **Application-based Cookies:**
    - **Custom Cookie:** Generated by your app. You must specify the name in the Target Group (cannot use reserved names like `AWSALB` or `AWSALBAPP`).
    - **Application Cookie:** Generated by the LB; named **`AWSALBAPP`**.
- **Duration-based Cookies:**
    - Generated by the LB with a fixed expiration period.
    - Named **`AWSALB`** (ALB) or **`AWSELB`** (CLB).

### Cross-Zone Load Balancing

![[Pasted image 20260311173912.png|632]]

- **ALB**
	- Enabled by default (can be disabled at target group level)
	- No charges for inter-AZ data
- **NLB** & **GWLB**
	- Disabled by default
	- You pay for inter-AZ data if enabled
- **CLB**
	- Disabled by default
	- No charges for inter-AZ data

### Connection Draining
- Time to complete in-flight requests while the instance is de-registering or unhealthy
- Stops sending new requests to the instance
- Between 1 to 3600 seconds (default: 300)
- Can be disabled
- Naming
	- CLB Connection Draining
	- ALB & NLB: Deregistration Delay

##### Notes
- All LBs have a static host name
- LBs can scale but not instantaneously, contact AWS for a "warm-up"
