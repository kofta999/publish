##### Content
CloudWatch Logs is the centralized logging service for AWS. While CloudWatch Metrics handles numbers, Logs handles the detailed text-based events generated by your applications and infrastructure.

#### 1. Log Hierarchy & Retention
* **Log Groups:** Usually represent an application or a specific service (e.g., `/aws/lambda/my-function`). You define retention and permissions at this level.
* **Log Streams:** Represent a specific instance, file, or container within that group (e.g., an EC2 instance ID).
* **Retention:** You can set logs to never expire or choose a window from **1 day to 10 years**.
* **Encryption:** Encrypted by default (AES-256). You can optionally use your own **KMS** keys for more control.

#### 2. Data Ingestion (The "Push" Model)
By default, EC2 instances do **not** send logs to CloudWatch. You must install and configure an agent:
* **CloudWatch Logs Agent:** The legacy version. Only pushes logs.
* **CloudWatch Unified Agent:** The modern recommendation.
    * Pushes **Logs** AND **System-level Metrics** (RAM, Disk space, Processes).
    * Configuration can be centrally managed using **SSM Parameter Store**.
    * Works on both EC2 and **on-premises** servers.

#### 3. Analyzing Logs (CloudWatch Logs Insights)
This is a serverless, interactive query engine. It is **not real-time** but is extremely fast for troubleshooting.
* **Query Language:** Uses a purpose-built syntax to `filter`, `stats`, `sort`, and `limit`.
* **Auto-Discovery:** Automatically identifies fields in JSON logs.
* **Cross-Account/Region:** Can query logs across multiple groups and accounts in one go.

#### 4. Exporting & Streaming (Real-Time vs. Batch)
This is a high-probability exam topic. You must choose the right tool based on the latency requirement.

| Method | **S3 Export (`CreateExportTask`)** | **Logs Subscriptions** |
| :--- | :--- | :--- |
| **Latency** | **Delayed** (up to 12 hours). | **Real-Time**. |
| **Use Case** | Archival, cold analysis, compliance. | Immediate processing (Lambda), near real-time ETL. |
| **Destinations** | Amazon S3 only. | Kinesis Data Streams, Firehose, Lambda, OpenSearch. |
#### 5. Advanced Architectures
* **Subscription Filters:** Allow you to choose exactly which log events get sent to your destination (e.g., only send logs containing the word "CRITICAL").
* **Cross-Account Subscriptions:** You can aggregate logs from multiple accounts into a single centralized Kinesis Data Stream in a "Security" or "Logging" account.
* **VPC Flow Logs:** Capture all IP traffic information going to and from network interfaces in your VPC. These can be published directly to CloudWatch Logs for analysis with Insights.

### SAA Exam "Scenario" Table

| If the requirement is...                                           | Use This Feature:                                |
| :----------------------------------------------------------------- | :----------------------------------------------- |
| "Monitor the **RAM usage** of your EC2 fleet."                     | **Unified Agent** (RAM is not a default metric). |
| "Search for 'NullPointerException' across 50 Lambda functions."    | **CloudWatch Logs Insights**.                    |
| "Stream logs to an OpenSearch cluster for real-time dashboarding." | **CloudWatch Logs Subscriptions**.               |
| "Keep logs for exactly 365 days and then delete them."             | **Log Expiration Policy** (Retention).           |
| "Export logs to S3 every 24 hours for audit compliance."           | **S3 Export** (batch).                           |
| "Centralize logs from 10 different AWS accounts."                  | **Cross-Account Log Subscriptions**.             |
